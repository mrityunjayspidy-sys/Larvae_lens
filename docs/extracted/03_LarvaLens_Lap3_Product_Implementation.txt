Lap 3 - Product Architecture Before Vibe
Coding
5.1 Build one installable PWA, not three client applications
Lap 3 builds one responsive React PWA. It runs in desktop browsers, adapts to phone screens and
supports Add to Home Screen. Do not attempt React web + Flutter + Kotlin during the same eight-hour
build. Native packaging is a later option after the web product works end to end.

5.4 Real-time status path
 text
Web POST /api/v1/scans with JWT + video
  -> API validates token, file and model readiness
  -> API creates real `scans` row with status=queued
  -> API uploads source video to private storage
  -> worker updates status: validating -> detecting -> verifying -> tracking -> completed
  -> Supabase Realtime publishes each row update
  -> Web progress screen updates from the actual row
  -> completed result fetches tracks and signed evidence URL
During initial development with no models present, the flow ends at a real error state: 503
MODEL_NOT_READY. This is deliberate and testable. It prevents the UI from being built around fictional
output.

Lap 3 - Structured Vibe-Coding Prompts
12.1 How to use these prompts
 1. Create the six Markdown files exactly as Documents 01-06 above.
 2. Start a fresh coding-tool conversation and attach/paste all six documents.
 3. Paste Prompt 00 once.
 4. Paste Prompts 01-10 one at a time, in order.
 5. After every phase, run the requested checks and provide errors back to the same conversation.
 6. Do not ask the tool to "build everything" in one prompt; that encourages skipped migrations, fake
 data and disconnected pages.
12.2 Prompt 00 - permanent source-of-truth guardrail
 text
You are implementing LarvaLens. The attached files 01_PRD.md, 02_TRD.md,
03_APP_FLOW.md, 04_UI_UX.md, 05_BACKEND_SCHEMA.md and
06_IMPLEMENTATION_PLAN.md are the source of truth.
Non-negotiable rules:
1. Build one responsive React/Vite/TypeScript PWA and one Python/FastAPI API.
2. Use Supabase Auth, Postgres, private Storage and Realtime; use Leaflet for maps.
3. Do not train, generate, download or substitute any ML model.
4. Do not call Gemini, OpenAI or any external vision API for inference.
5. Lap 1/Lap 2 will supply these required files later:
   - models/active/larva_detector_best.pt
   - models/active/larva_debris_verifier_best.pt
   - models/active/model_manifest.json
   Optional: larva_species_best.pt, disabled by default.
6. Do not add production mock data, seeded scans, random counts, hard-coded
   predictions, simulated progress or sample hotspots.
7. If model artifacts are absent or their SHA-256 does not match, expose
   models_ready=false and return HTTP 503 MODEL_NOT_READY from analysis.
8. Frontend must display the real unavailable/error state; it must never replace
   the error with a demo result.
9. Supabase service-role credentials stay in the API only. RLS is mandatory.
10. Preserve raw model evidence. Human reviews are separate records.
Work phase by phase. Before editing, state which files you will create/change.
After editing, provide:
- files changed,
- commands run and exact outcome,
- unresolved errors,
- manual setup still required,
- a phase acceptance checklist.
Do not begin implementation yet. First read all six documents, identify any
direct contradiction, and return a concise architecture/folder plan. Do not
change the locked stack or invent missing product behavior.
Expected response: architecture review only. Resolve genuine contradictions before Prompt 01.

Troubleshooting Guide
14.1 Colab runs out of GPU memory
 - Keep batch=-1; if it fails, set detector batch to 8 or 4.
 - Reduce detector imgsz from 640 to 512 only after recording the change.
 - Close other GPU notebooks; one T4 should not run multiple trainings in parallel.
 - Do not enable RAM cache for 8k high-resolution images; cache="disk" is safer.
 
14.2 Classification download count differs
This is expected across dataset versions or because metadata images were excluded. Use the Cell
L1-11 accepted, exact-unique count and save its manifest. Check unknown species paths before
training.
14.3 YOLO source structure is not discovered
The merger expects image paths containing an images directory and corresponding paths under
labels. If your ZIP is different, inspect one image/label pair and modify only label_for_image. Do not
rename data blindly until the mapping is confirmed.
14.4 Very high validation score but poor phone video
Likely domain shift or leakage. Check exact/near duplicates, microscope vs field mix, sequential frames
across splits, crop scale and lighting. Field-video metrics take priority for the demo claim.
14.5 Verifier labels every crop as larva
Check class balance, negative human review, class-directory names, train/val leakage and threshold.
Ensure the loaded file is the binary verifier, not the optional species classifier.
14.6 Count grows every frame
The backend is counting detections rather than unique persistent track IDs. Count only accepted final
tracks. Confirm ByteTrack persistence and video frame sampling.
14.7 Realtime UI stays queued
Check backend writes, Realtime publication, RLS visibility, exact scan ID filter and subscription cleanup.
Add a refetch fallback; do not simulate progress locally.
14.8 Vercel frontend cannot reach local API
A public HTTPS page cannot reliably call an unreachable laptop URL. For the judging table, use both
devices on the same LAN with an appropriate reachable frontend, or expose the persistent API through
